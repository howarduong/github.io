在使用BigWorld创建游戏内容时, 你需要建立一个安全有效的并可控制未来潜在的大量的生产数据管理方式.

理解文件资源的架构, 结合有效的版本控制软件, 可以帮助美术人员更好的了解和学习整个制作内容概要课程.

字母盘

在整个开发过程中，保持字母使用的一致性（大写/小写）非常重要。

虽然 BigWorld 工具和Windows系统对字母的大小写没有感觉， 但是BigWorld 服务器和一些在Linux系统上运行的脚本对此非常敏感。 当服务器脚本中有一个对应于美术资源的名字不一致的话就会发生问题。

对于这个原因，我建议所有美术资源都以小写字母命名。

为了防止因为大小写隐患导致未来开发问题，我们建议使用一些版本控制软件来防止大写字母的文件名递交。

整理美术资源 - Sets

我们试图构建整个资源系统使之在开发过程中尽量简化, 让大家有更多的时间用在实际开发上. 下面详细介绍了我们是如何整理常用资源,使之更友好. 我们提供了一个空的结构目录给大家, 请在 \bigworld\doc\tools_tutorial_examples 文件中的 tutorials\empty_file_structure\res 下找到. 你可以直接copy到你们自己的游戏架构下

虽然对于美术资源的位置可以比较随意 (只要注意在 res 路径下就好), 我们建议下述结构很有效:

把相关的场景按组放在sets文件夹下面. 下例 res/sets/temperate 内都是一个室外热带场景的文件.

结构目录

在每个 sets 下面有下列子文件夹:

flora-保存flora相关的模型,材质,贴图等文件 flora objects定义.

materials-包含此场景相关的 material *.mfm.

props-下存放道具的 visual, model, primitive, 和 texture 文件.

shells-包括壳相关 shell visual, model, primitive,和 texture文件. (壳类型的模型必须方在文件夹 shells).

如果游戏世界中有很多样式的道具, 那么props文件夹很可能变的一团乱

.

对于每个系列的容量都有你们自己定义, 并用次级结构细分同类的对象.不过我们建议控制次级文件夹的分类, 减低世界编辑器在定位资源文件树所花费的时间.

角色 - Avatars和 NPC's

Avatars (玩家控制角色) and NPC's (自主角色) 不是包含在set组别下的. 所以比多数的 BigWorld 对象复杂.
所以它们有独立的文件夹.

角色文件夹树

次结构中的文件夹包括:

res/characters-常规角色文件

avatars-对avatar分类建构次级文件夹保存不同类别的对象. knight 文件夹包含了骑士avatar的model, visual, primitives, LOD, 和 贴图文件.

animations-包括了角色间共享的动画文件.

npc-每个NPC一个文件夹. crow 中就包含了crow所有的 model, visual, primitives, LOD, 和贴图资源.

其他常用资源

没有和特定set相关的资料还是存在res的次级文件夹中的.

非特定资源结构

案例中的文件夹包括了:

res/flora-非set特定的flora 对象的 visual, model, primitive, 和贴图等资源

res/maps-包括了一些set间共用的资源, 比如一个特定的alpha贴图,在粒子系统中用到, 并且在一些shimmer效果对象上也用了. 就会被存在这个文件夹中.

res/maps/fx-对于通用的特效所用到的 visual, model, primitive文件, 例如爆炸的残片, 它不属于任何特定的set.

res/maps/particles-包括粒子系统用到的贴图.

地面贴图

地面贴图都被归在 (res/maps/terrain) 就是为了防止和其他贴图混淆. 世界编辑器只能显示在这个文件夹中的贴图. 如果你需要存储自己的地面贴图到不同的文件夹,就需要编辑世界编辑器的 Asset Browser.

原始创建文件的整理

原始资源是开发过程中的必然产物, 无论是3D文件Max / Maya,或者 2D 程序 Photoshop 的资源.根据过去的经验,我们对于如何整理这些资源给出如下意见l:

原始文件都在本地创建编辑, 再复制到局域网并和其他美术人员共享. 任何的修改,我们都建议先在本机完成在更新到网络上.

讲最后的原始文件copy到本地的资源文件结构下, 并更具对象类型做合适的分类, 其中包括了3ds Max 文件和PSD Photoshop文件 (贴图用).

考虑使用版本控制软件, 例如CVS, 需要最后更新每个场景的最终文件到服务器上. 这对于跟踪文件修改和回收前期版本很有帮助.

Asset Browser的使用

Asset Browser 是BigWorld创建工具WorldEditor, ModelEditor和 ParticleEditor中的一个资源辅助工具. 它在每个工具的asset标签下.

在使用 Asset Browser时可以独立出这块面板,通过拖拽它的标签就可以放到到屏幕的任意位置(包括双显).

Asset Browser 面板截图

Asset Browser 的面板是一个滤镜,而不是文件结构. 如果你选择 Models 文件夹, 那么在 Asset browser 中,你只会看见那些在规定路径下的文件集合.resource paths 规则定义在ual_config.xml 中 .

同理如果你选择 Textures 那么Asset browser 中只会显示符合过滤规则的文件. resource paths 规则定义在ual_config.xml 中

Asset Browser 面板– 使用搜索功能

通过search field的过滤,显示的文件会是,包含关键字在文件名中的文件. 例如,上图中因为输入了"ranger"并选择models文件夹,所以仅显示出包含ranger名的两个model文件.

如果你需要看文件结构,你可以展开次级文件夹列表.但这些文件夹路径必须要在resouce path中定义过的.

Asset Browser面板– 打开visual类别的文件夹结构

可以通过收藏夹收集常用的文件. 只要在浏览器中拖拽文件到收藏夹中就可以了, 任何类型的文件都可以放在里面.

有三种方式可通过 Asset Browser打开/添加文件.

在WorldEditor, 文件可以通过回车把选中的模型添加到世界中.

在所有的工具中, 都可以直接拖拽文件到预览面板

在 ModelEditor 和 ParticleEditor,也可以通过双击文件名打开.

自定义 Asset Browser

虽然多数的文件夹都直接在 resource paths 中指认, 还是有一些例外的

Particles 的虚拟文件夹只在 res/particles 中搜索

世界编辑器中的 Textures 虚拟文件夹只显示 res/maps/terrain 文件.

这些规则可以通过修改 ual_config.xml改变, 文件位于mf/bigworld/tools/BigWorldTool/resources/ual/ual_config.xml. XML可以用记事本编辑.

在 ual_config.xml 中,你找到标签 <Files> "FolderName" 定义了他虚拟文件夹下会搜索的范围. 下例中显示了粒子的搜索路径

<Files> Particles
   <path>           particles                                </path>
   <disableFilter>  Models;Shells;Prefabs;Trees;Entities;XML </disableFilter>
   <folderExclude>  *CVS;*/spaces;*/.bwthumbs                </folderExclude>
   <extension>      xml                                      </extension>
   <thumbnailSize>  1                                        </thumbnailSize>
   <showSubfolders> true                                     </showSubfolders>
   <showFiles>      true                                     </showFiles>
</Files>

如上所示, Particles会搜索 res/particles.

<Files> Particles
   <path>           particles                                </path>
   <path>           temperate/particles                      </path>
   <disableFilter>  Models;Shells;Prefabs;Trees;Entities;XML </disableFilter>
   <folderExclude>  *CVS;*/spaces;*/.bwthumbs                </folderExclude>
   <extension>      xml                                      </extension>
   <thumbnailSize>  1                                        </thumbnailSize>
   <showSubfolders> true                                     </showSubfolders>
   <showFiles>      true                                     </showFiles>
</Files>

修改成上例后, 现在它同时搜索res/particles和 res/temperate/particles.
