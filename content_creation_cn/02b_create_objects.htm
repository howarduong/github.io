3ds Max 和 Maya 导出路径

先花一些时间来设置导出路径可以节省日后在导出模型或动画时指定路径所浪费的不必要的时间和麻烦. 你需要将导出的模型和动画存放在 yourgame/res 下某子文件夹下.所以请把路径指向这样的位置.

3ds Max 的Customise菜单下 - Configure User Paths. 现在编辑Export 路径到你的游戏下.

 

在 Maya中 你可以设置一个BigWorld项目,并将导出路径直接指向你所希望的位置.

File -> Project -> New

设置项目名为 BigWorld 并设置 BigWorldAsset 到你游戏的res路径.

 

注: 导出器必须在所有以上设置步骤前完成. 请参考内容制作工具参考指南 安装导出器.

Maya 单位和世界坐标设置

BigWorld Maya 导出器识别在 Preferences中设置的 Working Units (菜单路径 Window→Settings/Preferences ).

Maya 中的1米就等于BigWorld世界中的1米.

因为MAYA不能设置系统单位, 所以无法通过导出缩放由玛雅制作的模型. 所以在进行绑定和动画步骤之前必须检查模型的尺寸是否无误. 在绑定骨骼后缩放模型通常会引发很多问题. 强烈建议正确的单位设置和检查.

如果你使用过旧版的BigWorld导出器, 以10 Generic Units = 1 Metre, 只需要在高级属性advanced settings 中勾选 "Use decimetres (ignore maya units)" 就可以了.

Maya 偏好设置对话框

BigWorld 导出器认定世界坐标系中Y轴向上. 所以需要在Maya 中设置Up Axis为Y, 在MAYA中的正视图朝向也正为游戏世界中的正面方向.

我们不支持Z 轴向上, 导出模型的朝向会出问题.

 

对象尺寸限制

对象尺寸不可大于 (BigWorld 坐标系) X =100M, Y = 200M, Z = 100M (100M 宽 and 200M 高l).

如果一个物体超过了此尺寸, 引擎很难正确剔除物体,因为他一次占据多个chunk. 也肯能导致物体虽然在相机视野内,但是却消失不见.

导出器会阻止你导出超过此限制的物体,以 防止后续问题.

 

防止Z fighting

Z fighting 一般在当两个三角面 (表面) 彼此非常靠近, 而产生两个面的前后闪烁状况, 在相机移动式尤其明显.

为了防止这个问题的发生在制作过程中,我们需要保持两个面之间有一定距离.

此问题通常在角色的头发和衣服上很典型.

Z fighting 图示.

 

防止乱序问题

使用alpha blend的对象只有在使用同一材质的时候才能排序正确. 所以,如果你需要对物体的多个部分使用alpha blend, 必须保证那些部分的材质名称一致.

使用 Alpha-blended 的多边形在每帧渲染前排序, 如果两个透明物体互相缠绕,却没有使用同一材质,那么她门的排序就会出错.

这里是一些预防乱序的小窍门:

1. 不要对大面积的物体使用alpha blend.

2. 尽量不要将带alpha blend的物体 互相交错, 这样容易导致乱序问题.

3. 整合物体的带alpha blend的部分, 使用统一材质.

4. 需要注意的是, 所有使用alpha blended skinned模型,无法利用GPU计算.所有的透明计算都是由CPU 处理.

物体中心支点

你所使用的3D软件的世界坐标系原点 (0,0,0), 会被作为导入BigWorld引擎的物体的中心支点.

1 对象位置需要摆放正确, 这样才能确保到时候,中心点位于边界框的内部. 因为引擎更具物体的中心点来定义物体的位置的. 如果物体的中心点相对于物体有一定的距离的话, 很可能出现错误, 尤其是当需要共享两个chunk中的物体,或计算剔除的时候.

2 BigWorld 世界编辑器在放置对象时,利用中心点来做捕捉地面和捕捉物体表面的对齐方式. 所以在导出物体时,将物体放在原点位置是非常重要的.

前期多注意规范可以简化在时间编辑器中的操作. 比如, 下图中的树, 中心点位于,树根模型底线的上方, 这样在放到游戏中时,结合捕捉地面对齐方式, 就可以保证,树和地面更好的衔接, 不会出现空隙了.

在UV边界外保留出血框,防止贴图压缩出错

BigWorld 引擎自动压缩贴图, 并实用mipmap进程. Mipmap 技术会更具原图按比例压缩创建一系列的贴图. 这项功能节省了贴图内存的实用, 并有理游戏表现. 如果需要了解更多关于贴图压缩的信息, 可以参考章节 贴图压缩属性设置/Defining texture compression settings

mipmap举例

当贴图通过mipmap压缩时, 它对附近的像素点取样,得出新的像素信息. 如果环境像素是黑色的话,那么它新建的像素会比原来的要深, 这样所容易导致的错误, 可以很简单的通过下右图示来理解.

当从远处观察角色时(右图显示), 模型的中间出现黑色线条

为了防止mipmap压缩出现问题, 需要在UV边界外保留一定像素点的出血边框.

复合材质类型耗费量大

一个物体上使用越多的材质, 就会产生越多的drawcall, 显卡的计算量也越大. 这样会减低你游戏的表现, 所以最好对模型上的材质类型总量事先做个限制,以保证游戏效率.

这里有一些帮助提高游戏效率的建议:

1 减少复合材质类型的使用.

如果一个物体只有一个材质类型, 那么只有一个单一材质. 以一个货箱来打比方吧, 它是所有游戏设计的理想点缀品. 箱子只使用一个材质. 而最坏的状况就是你给它的每个面使用不同的材质类型. 应该在更重要的物体,例如玩家,角色上使用复合材质类型, 如果你坚持使用的话, 也请在制作它的LOD时, 使用单一的材质类型.

2 在LOD 中去除材质的类型变化

在远距离, 复杂多效的材质也变得效果模糊,可以忽略, 且只能拖累游戏引擎的表现. 所以在此建议,在设置LOD模型时,请减少或去除材质类型的多样化, 尽量使用简单单一的材质类型.

举例说明, 角色的第一个LOD, 距离镜头最近, 我们使用3种材质类型: metal, skin 和 hair, 每个使用一个不同的材质,并且使用多张贴图 (Diffuse map, Normal map, Reflection map). 而LOD3, 因为角色总共在屏幕上只占有几百个像素点, 所以只需要一个简单的材质并只需要一张diffuse贴图就可以了.这样可以大大降低显卡的负担.

3 共享贴图

物体不同的部分使用不同的材质,但是没有必要按部分将贴图分开. 最好一个物体一张贴图. 这样可以节省贴图内存D3D状态改变的耗费.下图例中的贴图包含所有模型部分,并被分别使用在模型的不同材质上. 虽然共享贴图但是每个使用独立FX材质的部分还是会需要一个独立的drawcall.

共享一张贴图给复合材质类型.

导出静态对象为 Visual 文件, 操作步骤如下:

首先, 确保你已经正确安装了导出器到你的3d程序上. 关于如何安装,你可以在 Tools Reference Guide工具参考指南中找到指示, 章节3ds Max and Maya Exporters.

此例使用res\sets\trees

资源次级文件结构

4 填写文件名 File Name 为 oak_tree.

5 Save As Type 导出类型下拉菜单中选择 Visual Exporter (*.VISUAL).

Save As保存类型类表

6 点击 Save.

7 在 Visual Exporter导出器界面中:

设置 Visual type为Static.

静态物体是没有蒙皮 (没有骨骼), 没有动画的物体. 如要了解如何导出一个动态角色或NPC到游戏, 请参考另一章 创建低模角色Create Low-Polygon Characters.

清空 Allow scale检查框.

Visual Exporter 对话框

点击 OK.
