光照环境

bigworld引擎中有两类光照环境:

室内照明

室外照明

室内照明

室内灯光只对壳内物体起作用,而且相对室外灯光的自定义属性更灵活.

天空入口(heavenly portal)允许阳光影响室内: 因为天空入口允许阳光进入壳内, 所有壳内物体会受到室内外灯光双重影响. 如果要营造纯室内效果, 就不可以用天空入口作为入口属性.

室内灯光是基于顶点计算的: 因为室内静态灯光是以模型顶点为基础计算的, 为了保证柔和自然的灯效需要保证壳内模型有足够的顶点,且布线均匀.更多的细节可以参考如何创建理想的壳内光环境, 参见在3ds Max中创建壳体和最佳练习.

 

室外照明

室外照明有两种选择. 你可以在世界编辑器中选择一个类型.

选择 1 (默认)

室外照明包含:

环境灯光

太阳 (方向性灯)

每个室外单元chunk可使用4个动态灯和2个高光灯.

此选择给你一个根据时间变化的动态的光影计算. 太阳会升起会落下. 投影在下午会变长. 我们支持动态的跟随时间变化的灯光,但是我们不支持(室外)静态的灯光.

一个典型的使用此选择的范例是 fantasy demo 中的 fantasydemo/res/spaces/highlands, 和 fantasydemo/res/spaces/min_spec

 

选择 2 (默认)

选择移除随时间变化的动态光,就可以在室外世界天价静态灯光了.

室外灯光包含:

环境灯

无限个数的静态灯

每个室外单元chunk可使用4个动态灯和2个高光灯.

这就等同于转换你的室外环境为一个巨大的室内世界.

一个典型的使用此选择的范例是 fantasy demo 中的fantasydemo/res/spaces/urban.

注: 位于室内(壳)的灯光在两个选择中都是一样的,没有区别.

灯光类型

有5种真实灯光,两种基于图像的灯光.

真实灯光

Ambient 环境灯– 每个室内分块只能有一个环境灯光,这类灯没有方向,并模拟背景光的饱和度

Omni泛光灯 – 以球型向外减弱辐射的灯光.

Spot 聚光灯–锥形灯光,类似闪光灯.

Directional 平行灯– 光线方向唯一且平行,一般不设选项添加更多的平行光

Pulse –泛光灯, 增效和位置都可做动画,真实的动态和镜面光源,它的定义文件是 bigworld/res/system/data pulse_light.xml,位置动画定义文件为 bigworld/res/system/animation/lightnoise.animation.

基于图像灯光(耀斑)

图像灯光并不真的发光, 她只是模拟灯光发散的特殊效果而已, 这里有两种:

Coronas光晕– 这只是一张总是面向镜头自旋的叠加效果贴图.常用来处理像烛光那样的晕光效果

Streak拖影 – 它包括两个部分,光晕和镜头眩光,如果配合亮光源可以得到很好的效果.

光照属性

每个真实灯光都集合了一下几个属性:

Static lights: 静态灯光只应用于静态室内场景物体.

尤其, 它指示静态灯光属性,也只作用在壳和壳内静态物体上,不对角色和任何动态物体起作用(例:可查看entities中定义).

静态灯光作用于顶点,你可以随意添加,没有个数限制,它的运算是不占任何网络资源,仅在本机完成.

静态灯光只作用于室内,室外不做添加.

Specular lights: 镜面光照,它可以作用在任何使用高光贴图的物体上,但仅对高光贴图起作用.

每个shell壳最多不超过2个镜面光缘.

注: 聚光灯不可仅仅使用镜面光照属性.

Dynamic lights: 动态灯作用与动态物体,例如角色和室外模型.

每个物体可接受的灯光不超过8个,引擎会自动选择最近的8个灯光进行计算, 并不是说壳内不可多于8个灯光,你可以任意添加, 但是每个物体只计算8个来作用自己

注: 所有的室外物体被默认为动态的,所以如果你在添加室外灯光时必须使用动态光属性

灯光布局

在布置某特定光环境,超过8个动态灯时,你需要测试防止意外效果,因为你不确定引擎如何选择组合灯光.为了避免意外发生, 请参考以下建议:

减少灯光数量.

减弱个个灯光强度.

确保每个灯光都有衰变,以便于在该对象从灯光范围移开时过度自然.

这8个灯光的组合条件:

最多4个泛光灯

最多2个聚光灯

最多2个平行光

下图解释了以下两种状况:

如何在壳内布置灯光,防止灯光"跳跃"–没有一个点会同时被8个动态光重叠作用.

如何保证主角在室内每个角落都可以收到镜面光作用.

当灯光个数限制超过时,引擎不得不考虑取舍,在要舍除一些灯光对于物体的作用时,參考因素有距离和灯光的辐射范围.

注意: 我们使用对象的碰撞体来计算灯光和它的距离.

 

显示灯光贡献作用

世界编辑器允许你显示哪些灯光对某一模型起作用。选择模型右键点击 - Visualise light contribution.

黄色连线表示活动的灯光作用，也就是做贡献的灯光。

灰色连线表示范围内却不活动的灯光作用，也就是不做贡献的灯光。（通常是因为灯光个数限制的原因）

灯光对场景的影响可以被强制执行, 方法就是通过调整它们在世界编辑器中Light Priority的设置.

创建和编辑耀斑

耀斑是一种在光源前附加的图片,通常被用作模拟镜头效果和增强光的强度效果. fantasydemo中太阳使用的耀斑文件可以在 bigworld\res\system\data 目录中找到.

太阳的耀斑 (fx_sun.xml) 是由一组耀斑组合而成. 当光源减弱, 会自动使用另一个耀斑 –这样模拟了当光源逐渐暗淡是产生的拖影.

当你自己创建耀斑文件时, 最好在现存文件上做修改. 耀斑在世界的添加是需要程序员支持的.

以下是一个分段式的太阳耀斑文件 fx_sun.xml (参见下面的注解):

<root>
   <maxDistance> 1000000 </maxDistance> A
   <area>        75      </area>        B
   <fadeSpeed>   0.1      </fadeSpeed>  C
   <Flare>
      <occlusionLevel> 0.5                        </occlusionLevel> D
      <type>           materials/fx/sun_flare.mfm </type>           E
      <size>           1.0                        </size>           F
      <secondaries> G
         <Flare>
            <type>    materials/fx/secondary.mfm </type>
            <size>    0.1                        </size>
            <depth>   0.3                        </depth> H
            <rgba>    255 128 0 48               </rgba>  I
         </Flare>
         <Flare>
            <type>    materials/fx/secondary.mfm </type>
            <size>    0.2                        </size>
            <depth>   0.2                        </depth>
            <rgba>    255 0 0 32                 </rgba>
         </Flare>
         <Flare>
            <type>    materials/fx/corona.mfm    </type>
            <size>    0.1                        </size>
            <depth>   -0.1                       </depth>
            <rgba>    255 255 0 32               </rgba>
         </Flare>
         <Flare>
            <type>    materials/fx/secondary.mfm </type>
            <size>    0.05                       </size>
            <depth>   -0.4                       </depth>
            <rgba>    128 255 0 32               </rgba>
         </Flare>
      </secondaries>
   </Flare>
   <Flare> J
      <occlusionLevel> 0.1                        </occlusionLevel>
      <type>           materials/fx/sun_split.mfm </type>
      <size>           1.0                        </size>
      <rgba>           255 255 255 128            </rgba>
   </Flare>
</root>

A maxDistance控制耀斑最远可见距离.

B area 定义在多大的视觉范围内有效, 而且被用来计算耀斑遮蔽,也表示了屏幕上的像素量.

C fadeSpeed 控制耀斑淡出但淡入的速度,越大的数值对应越慢的速度.

D occlusionLevel 这个数值表示了此耀斑层级最低可视量值, 如果世界低于此量,便自动使用下一级的耀斑.

E type 这是对耀斑材质的定义, 你可以直接定义效果文件,贴图或者MFM文件.

F size 对原始材质的缩放.

G secondaries 添加多层图片, 丰富单一的耀斑效果, 这些图片依次排列从太阳到镜头的中央, 这样就模拟了光线射过镜头的效果了.

H depth 规定从基本耀斑到第二级的距离.

I rgba 定义耀斑的颜色.

J 这是可以穿过树的耀斑, 如果光线渐暗引擎自动使用新一级耀斑. 如果彻底暗掉, 就没有耀斑产生. 至于渲染哪一级别的耀斑是通过对现有可见耀斑来推断的. 由 occlusionLevel 定义,参见 D
