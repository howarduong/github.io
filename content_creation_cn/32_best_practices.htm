使用游戏执行效率控制台( the Realtime Profiling Console)测试游戏运行表现

在client窗口界面 按下~(tilda) + F5就会显示 Realtime Profiling Console 游戏执行效率控制台

这里显示的是游戏效率损耗状况.

Fps: 每秒帧数

Visuals: 每屏场景中的模型个数

DrawCalls: 每屏场景中draw calls的总个数.

Primitives: 场景中所有图元个数.

Primitives/DrawCall: 平均每个drawcall中图元的个数.

如果这个数字很高的话,就表示美工使用了过多不必要的材质在模型上了. 过量使用复合材质会增加drawcall的数量,降低游戏效率.

Texture(Total): 所有已下载的贴图所占内存 (玩家周围的贴图)

Texture(Frame): 上一屏中所有贴图所占内存.

Heap Memory/Allocations (Current): 程序对当前内存分配的量/配额的数目

Heap Memory/Allocations (Peak): 此次运行中程序可以分配的最大内存量/配额的数目

你可以使用回车键展开,游戏执行效率控制台下,后缀有...的项目, 使用pageU和pageDan选择, "G"按钮可图表显示个个项目的执行效率.

 

使用客户端监测器来定义有问题的场景

使用~(tilda) +F7 显示debug console 控制台

使用 PageUp 和 PageDown浏览列表,使用'回车键' 选择要展开的项目和修改参数.

另一个跟有用的客户端监测器是 Debug Sorted Triangles. 当值设为 (1)的时候,场景会加深显示所有除了使用了 alpha blended 材质之外的对象.

使用 Alpha blended 的对象要求排序计算,所以会占有更多的游戏资源, 降低游戏表现. 你可以利用这个功能检查出游戏中那些其实并不需要使用alpha blend的对象. 例如岩石是不要用alpha blend的.

注: flora生态型使用alpha blending是没问题的.

 

测试portal剪切渲染

你可以利用监测器和线框显示模式检查portal裁剪渲染的效率.

用~(tilda) + F7再展开Render 目录下选项设置 draw portals 为true (1).

会在所有portal周边显示红线,这样帮助视觉识别portal的位置.

按~(tilda) + F8 三次,整个世界变成线框显示模式.整个世界可以被透视,所以可以方便的辨识出哪些物体被渲染,哪些被剪切了.

树动画 - 利用LOD模型共享动画

BigWorld支持角色间的动画共享, 前提是所有绑定的骨骼结构和命名一致, – 动画共享的方式是使用同一个LOD模型.

建议只在使用完全相同的骨骼配置的角色之间共享动画. 如果在不同大小形体的模型上共用动画,会导致模型顶点因为共享骨骼的大小而拉扯导致模型变形失真.

以下步骤形容了如何共享动画 (具体设置可参考下面的截图):

1 动作匹配程序调用要在游戏中播放的动画.

2 需要对当前渲染的 LOD 模型进行检查，看看其动画是否合适. 如果不合适，动作匹配程序会沿 LOD 树向下查找（进一步调用 LOD），检查动画是否合适

在下例中,如果 ranger.model被渲染, 要求调用walk动画,这时ranger.model 模型调用的男性 walk 动画是基于 base.model下的. 因为在ranger.model和rangerlod.model的动画库里没有自己特定的walk动画.

动作匹配程序不会向上层搜索动画树, 所以在下例中, 如果渲染的是 loddy.model模型, 如果要调用的动画是 ranger.model动画库里的firegun_ranger , 则没有动画被播放.通常情况下 这不能算是一种错误,因为 loddy.model 渲染位置太远,以至于无法看到此动画,在这么远的位置无法辨识的动画将不被调用播放,如此也提升了游戏效率.

批渲染

如果有一个物体,在游戏中每屏重复出现多于3次, 那么使用批处理可以大大提高游戏的效率.

无论是静态的还是带动画的物体都可以使用批处理渲染,这个属性在模型编辑器的物体属性面板中设置.

带有material tint 或者 alpha blended 的物体是不可以使用批渲染的.

DPVS 和 Umbra

dPVS 和 Umbra 是第三方遮蔽剔除算法,能很好地提高绘制效率的可见性计算的系统

DPVS

遮蔽剔除是在 CPU上运算的, 把物体作为阻挡物会增加一些额外运算量.因此,只把自身条件很的物体标识为阻挡物很重要.例:类似墙,房屋等大型物体. 如果很小的物体被用作阻挡物的话会降低游戏性能.

把物体标识为阻挡物.

Umbra

遮蔽剔除是在显卡上计算的,所以并不会因为把物体作为阻挡物而增加运算量.Umbra也不需要美工手动设置.

Umbra 理解 BigWorlds 的portal系统, 所以可以通过利用壳和其附件等几何体来做遮挡剔除,提高portal渲染的性能.

为DPVS和Umbra创建文件

Umbra基本上是使用视线来定义是否物体需要绘制的. 因此, 确认模型是否阻在视线内阻挡其他模型是非常重要的(墙壁, 壳, 房子), 所以这些模型也必须非常规整. 好的,规整的模型的形体必须满足没有洞, 没有未焊接的顶点, 或者开裂的边. 如果模型上有洞和缝,那么它不仅无法正确的做渲染遮蔽,还会导致减低的游戏效率.你可以在世界编辑器或者客户端预览时, 通过开启场景线框模式来检查渲染剔除问题. 如果在墙体或者房屋的后方有模型被渲染,则意味着有问题.

你可以通过~(tilda) + F8在客户端开启线框模式, 或者世界编辑器的选项面板.

 

3dsMax' 的STL Check 编辑器可以找出模型上的破点,开边等问题.

Maya中也有一个类似的工具叫做 polygon cleanup. 菜单: Mesh - Cleanup.

模型编辑器中, 显示面板下 Check For Sparkles 也可以用来找出模型的破面. 它会將模型渲染为黑色,而背景为白色, 这样你就可以很容易的发现破开的面和裂缝.

使用用户接入工具Client Access Tool (CAT)

用户接入工具Client Access Tool (CAT)方便你快速利用GUI图形使用者界面来执行 Python脚本.

虽然 CAT 已经附带了一些基本命令, 它其实更可以算是一个可被高度自定义的工具框架. 如果你需要美工在开发过程中经常使用python命令的话 CAT 就是一个实用的工具了.

CAT 的位置在 bigworld/tools/cat/cat.bat. 先运行client(游戏) 再简单的使用这个程序就好了.

如果要编辑CAT必须安装 Python和wxPython, 通过网络搜索都可以找到.

使用 SpeedTree

广告板

为了达到更好的视觉效果以及游戏效率, BigWorld的3D引擎以十字交叉的四边形渲染树广告板,而不会自动转向镜头.

对于每颗树，虽然三块广告板能成最佳的视觉效果，BigWorld 的 3D 引擎仍会将广告板渲染 360 度并以复合材质形式保存。如果导出贴图可用,Bigworld还会将渲染一个水平广告板。

在导出树时, SpeedTreeCAD 预渲染广告版到复合贴图中. 因此, 只有当树的种子号一样时导出 spt 文件.它的广告版才能完全和树匹配.
确保导出树BigWorld使用统一种子号,在世界编辑器中都设成1.

优化

Bigworld引擎使用一下技术帮助提升游戏效率:

Instancing关联复制 – 内存中保存一份但可用于所有的关联复制对象.

Batching批处理 – 在渲染树的时候,Bigworld引擎对基元排序,以减少由于对所有树多个层级的渲染的需要.

Compounding合成– 树被一起编译,减小顶点缓冲,也减少了draw call的渲染.

树的总量:树的总类,比率越高,也表示上面的技术使用效率越高. 因此，为尽可能充分利用时间并节省内存，游戏世界构建者必须尝试将游戏世界中所放置的不同树的数量降至最低.

不同的树指的是使用不同spt 源文件, 或不同树种子号码.

由于合成较多细节的树需要较高的内存和处理，因此，合成技术只应用于广告板.

为了能够使用单一绘图调用来渲染广告板，必须构建在所有视角都包含所有树类型广告板的纹理拼图。 这是由引擎自动完成的，但游戏世界构建者可能需要调整的纹理拼图的大小，以承载所有需要的广告板

如果此纹理拼图不够大，容不下所有广告板，则将向调试输出发出警报，且广告板将开始在纹理拼图中相互重叠，导致纹理贴图错误.

有关如何调整纹理拼图的详细信息，请参阅 SpeedTree 的 XML 配置文件中的 billboardOptimizer 部分. SpeedTree 的配置文件名称在文件 resources.xml 中指定，此文件位于游戏的资源文件夹中，如下图所示:

锁定服务器;同时编辑同一世界

锁定服务器工具 (bwlockd) 可以让多方同时对一个世界编辑, 而又不互相覆盖对方的修改. 因为它支持锁定工作区域, 这样只有修改者可以有权限对这块区域做修改.

锁定服务器工具必须再一个所有机器都能连接的机器上运行, bwlockd.py 脚本位于bigworld/tools/bwlockd.

要连接一个 bwlockd 服务器,每个用户必须修改他们的世界编辑器 options.xml文件来连接服务器. 

	<bwlockd>
		<use>	true	</use>
		<host>	</host>
		<username>	</username>
		<xExtent>	5	</xExtent>
		<yExtent>	1	</yExtent>
	</bwlockd>

当一个用户第一次连接的时候,整个世界都显示红色,而且他不能编辑任何对象.

如果想要锁定和编辑一定的区域,请选择空间投影视角 , 于是你就可以看到一个顶视的世界投影全景.

框选你想要编辑的区域. 框选的遮罩会带有两个区域, 1.内圈是你可编辑的区域, 2.外圈是对于所有用户都锁定的区域.这个外部的框的默认设置为,纵向的1个chunk, 横向5个chunk

在消息框中填写处理信息

点击锁定分块, 于是服务器锁定工具便通知数据源控制软件,你正在使用并确认你使用这些分块的最新版本来继续编辑.

一旦这些分块被锁定了, 那么这些区域的颜色会在3D视图中恢复正常,现在你就可以编辑这个世界了.

当你完成了编辑,你可以选择 放弃所有更改或者保存并提交 你的修改. 每个按钮都可以勾选 提交后保持锁定状态 , 这样会保留之前选定区域的锁定状态

请注意,即时你关闭了世界编辑器,此块区域还是保持锁定状态, 也就是只有你拥有编辑的权限. 如果要让其他人可以在此区域工作,切记要对取消锁定.

修改锁定边界和其效果

世界编辑器必须锁定你所编辑的区域周围一圈来确保地面投影的一致性. 这是因为在Bigworld 引擎中的对象在横向(东西向)上的投影长度最大范围是5个chunk的距离. 锁定了这块区域来保证在开发过程中你所编辑范围内物体的投影始终一致. 然而这个锁定的范围比较大,也许在开发过程中, 因为世界大小以及同时被编辑开发的区域大小关系, 可能不利于操作.

如果锁定的区域变得庞大不便, 那么锁定东西向chunk的个数可以被修改, 在文件options.xml 中把 <xExtent> 的值设定为1 就好了.不过修改了锁定范围后, 你必须在世界编辑完成后对整个世界运行 process all 项目- 对所有数据进行处理.

世界编辑器通常会自动关注哪些chunk需要重新计算投影, (脏的chunk). 修改了 <xExtent> 标签会导致世界编辑器的监察效果松懈. 为了保证整个世界的投影正确, 整个世界的chunk 都需要被设定为 dirty, 脏的, 你需要通过 python控制台来完成设定.

方法如下:

1.在世界编辑器界面中按下 Ctrl + P 进入phython 控制界面

2.输入命令

WorldEditor.touchAllChunks()

现在,所有的chunk 都被认定为脏的,既被修改过的, 所以这个世界必须运行 process all 项目- 对所有数据进行处理., 注意这将花费非常多的时间去完成.
